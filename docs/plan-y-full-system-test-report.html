How The System Works

1. Record Pagedbg record <url>

Starts managed headless Chrome, opens the recorder session, installs mutation/perf/flow bindings, and stores captures in SQLite plus blobs on disk.

2. Record Flowdbg flow record <name> [--url]

Optionally navigates to the flow URL, then listens for capture-phase click, change, keydown, scroll, and navigation actions through __dbg_flow__.

3. Persist Stepsflow_steps

Each action is stored with kind, selector, fallback path, value, and index. Selector priority is unique id, data-testid, unique class selector, then nth-of-type path.

4. Replay Flowdbg flow run <name>

Starts from the flow URL, waits until each target is visible and hit-testable, replays trusted CDP input, captures after every step, and stores verdicts.

5. Query Evidencedbg q

flows, flow_steps, flow_runs, and flow_run_steps expose the whole process to SQL and downstream automation.
