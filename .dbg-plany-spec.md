## Step 1 — Recording

- installs a **capture-phase** selector generator `sel(el)`: `#id` if unique id; else `[data-testid="..."]`; else unique `tag.classA.classB` if that CSS matches exactly one element; else an `nth-of-type` path from `<body>`. ## Step 2 + 3 — Replay engine + per-step verdict
`flow.run` requires an active recorder (drives `recorder` page session). Handler `handleFlowRun(name, stepTimeoutMs)`:
1. Resolve newest flow row by name; load its steps ordered by idx. If none → err.
2. Navigate the recorder page to the flow's `url` (`Page.navigate` + `waitForPageLoad`), so replay starts from a clean documented state.
3. Insert a `flow_runs` row (status filled at end). For each step in order:
   - `stepStartTs = Date.now()`.
   - **readiness poll** (interval 100ms, deadline `stepTimeoutMs` default 5000): `Runtime.evaluate` a fn that `querySelector(step.selector)` (fall back to `step.fallbackPath` if selector misses); require nonzero `getBoundingClientRect` AND `document.elementFromPoint(center)` returns the element or a descendant/ancestor. Return `{ready, cx, cy, reason}`. Poll until ready or deadline.
   - if not ready by deadline → step **failed**, `error = "readiness timeout: <selector> not actionable (<reason>)"`; STILL do a `forceRecorderCapture` so the row gets a `capture_id`; insert flow_run_step (status=failed); mark all remaining steps status=skipped (with their own capture_id from a single final capture is unnecessary — skipped rows may have null capture_id, but attempt a capture for the failing one). Break the loop (fail-fast).
   - if ready, execute by kind using flow-replay.ts helpers:
     - `click`: `DOM.querySelector` → `DOM.scrollIntoViewIfNeeded{nodeId}` → `DOM.getContentQuads{nodeId}` → center of first quad → `Input.dispatchMouseEvent` mouseMoved/mousePressed/mouseReleased (trusted). (Fallback to `DOM.getBoxModel` centroid if getContentQuads returns none.)
     - `input`: `DOM.focus{nodeId}` → `Input.insertText{text: step.value}` (React-safe). Optionally clear first via select-all not required.
     - `keypress`: `Input.dispatchKeyEvent` keyDown+keyUp with `key`/`code`/`text` derived from step.value (Enter → key:"Enter",code:"Enter",text:"\r"; others map sensibly).
     - `nav`: `Page.navigate{url: step.value}` + `waitForPageLoad`.
     - `scroll`: `Runtime.evaluate window.scrollTo(0, value)`.
   - **verdict**: wait for a mutation ping OR 500ms (whichever first — simplest: `await sleep(500)`), then `forceRecorderCapture(session)` → captureId; `consoleDeltaSince(session, stepStartTs).errors` → step errors; diff-vs-last-run: find the previous run's flow_run_step for the same `step_id` with a capture_id, load both capture pngs, `diffPngs` → diffPercent (null if no prior). Insert flow_run_step (status=passed unless console errors present → still passed but errors surfaced in summary; readiness is the only hard failure for the e2e).
4. Update flow_runs status = failed if any step failed else passed; steps_passed count.
